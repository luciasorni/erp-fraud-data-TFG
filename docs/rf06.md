# RF06 - Trazabilidad y Drilldown Bidireccional

Este requisito cubre cómo reconstruir el origen de un hallazgo a partir del ranking/salida estándar, sin SQL libre.

## Objetivo

Dado un hallazgo (`entity_key`) de un test ejecutado, recuperar filas origen en DuckDB con consulta segura parametrizada.

## Componentes implementados

- Keys mínimas por test:
  - `src/erp_fraud/catalog/drilldown_keys.py`
- Plantillas seguras (`query_id` allowlist):
  - `src/erp_fraud/catalog/drilldown_templates.py`
- Ejecución de drilldown con validaciones de seguridad:
  - `src/erp_fraud/catalog/drilldown.py`
- CLI:
  - `src/erp_fraud/cli/main.py` (`drilldown`)

## Controles de seguridad

- Solo se permiten tests del catálogo (allowlist).
- Solo se ejecutan plantillas predefinidas por `query_id`.
- No se acepta SQL libre.
- `limit_rows` máximo: `200`.
- Filtros extra limitados por allowlist de columnas.

## Ejemplo completo (end-to-end)

1. Ejecuta tests (o usa un `run_id` existente) y localiza un `entity_key` en resultados:

```bash
cat run_results/<run_id>/tests_outputs/TST-UNUSUAL-AMOUNT-BY-VENDOR/findings.jsonl
```

2. Lanza drilldown por `run_id`, `test_id` y `entity_key`:

```bash
python3 -m src.erp_fraud.cli.main drilldown \
  --run-id <run_id> \
  --test-id TST-UNUSUAL-AMOUNT-BY-VENDOR \
  --entity-key "betrag=10296.0|kreditor=V1024"
```

3. Opcional: guardar el resultado en ruta explícita:

```bash
python3 -m src.erp_fraud.cli.main drilldown \
  --run-id <run_id> \
  --test-id TST-UNUSUAL-AMOUNT-BY-VENDOR \
  --entity-key "betrag=10296.0|kreditor=V1024" \
  --output run_results/<run_id>/drilldowns/example_unusual_amount.json
```

4. Resultado esperado:

- Se devuelve un JSON con filas de `fraud_1` que explican el hallazgo.
- El número de filas no supera `200`.
- Si faltan keys mínimas o hay parámetros no permitidos, devuelve error controlado.
