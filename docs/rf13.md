# RF13 - Catálogo ampliado ACFE (selección inicial)

## RF13-01 completado

Objetivo de esta tarea: seleccionar y priorizar una lista de **10-20 tests** del catálogo ACFE
(`docs/external/data_analytics_tests.pdf`) que sean viables con el dataset actual.

Contexto técnico usado para priorizar:

- tabla base disponible: `fraud_1`
- columnas clave disponibles: `Kreditor`, `Belegnummer`, `Position`, `Betrag`, `Transaktionsart`,
  `Erfassungsuhrzeit`, `Buchungsschluessel`, `Sachkonto`, `Material`, `Menge`,
  `Soll/Haben-Kennz_`, `Zahlungsbedingung`, `Zahlungssperre`, `Steuerkennzeichen`
- esta fase prioriza tests sin depender de maestros externos (`vendor master`, `employee master`, etc.)

Referencia de cobertura real del proceso P2P (qué cubrimos hoy y qué no):

- `docs/p2p_coverage_and_gaps.md`

## Lista priorizada (12 tests)

### Prioridad P1 (implementación inmediata)

1. `TST-DUPLICATE-POSTINGS`  
   ACFE: *Identify duplicate purchase order numbers, credits, and invoices*  
   Viabilidad: alta  
   Columnas base: `Kreditor`, `Belegnummer`, `Position`, `Betrag`

2. `TST-UNUSUAL-AMOUNT-BY-VENDOR`  
   ACFE: *Unusual transaction amounts / reasonableness checks*  
   Viabilidad: alta  
   Columnas base: `Kreditor`, `Betrag`, `Transaktionsart`

3. `TST-ROUND-DOLLAR-PAYMENTS`  
   ACFE: *Review transactions for round-dollar payments*  
   Viabilidad: alta  
   Columnas base: `Betrag`, `Kreditor`

4. `TST-JUST-BELOW-AUTH-THRESHOLD`  
   ACFE: *Review transactions just under authorization thresholds*  
   Viabilidad: alta  
   Columnas base: `Betrag`, `Kreditor`, `Belegnummer`

5. `TST-SPLIT-PAYMENTS-NEAR-LIMIT`  
   ACFE: *Split payments exceeding authorization limits*  
   Viabilidad: alta  
   Columnas base: `Kreditor`, `Belegnummer`, `Betrag`, `Erfassungsuhrzeit`

6. `TST-INVOICE-SEQUENCE-GAPS`  
   ACFE: *Review payments with little or no sequence between invoice numbers*  
   Viabilidad: alta  
   Columnas base: `Belegnummer`, `Kreditor`, `Erfassungsuhrzeit`

7. `TST-NEGATIVE-QUANTITY-RECEIPTS`  
   ACFE: *Identify negative receipt quantities*  
   Viabilidad: alta  
   Columnas base: `Menge`, `Material`, `Kreditor`

8. `TST-DUPLICATE-MATERIAL-ITEMS`  
   ACFE: *Identify duplicate items or serial numbers*  
   Viabilidad: alta  
   Columnas base: `Material`, `Belegnummer`, `Position`, `Kreditor`

### Prioridad P2 (segunda ola, aún viable)

9. `TST-HIGH-INVENTORY-COST-OUTLIERS`  
   ACFE: *Identify higher-than-average inventory costs*  
   Viabilidad: media-alta  
   Columnas base: `Material`, `Betrag`, `Menge`, `Werk`

10. `TST-UNUSUAL-POSTING-TIMES`  
    ACFE: *Review transactions posted at unusual times*  
    Viabilidad: media  
    Columnas base: `Erfassungsuhrzeit`, `Kreditor`, `Betrag`  
    Nota: sin fecha completa, se arranca por horario atípico intradía.

11. `TST-LARGE-EVEN-DOLLAR-ENTRIES`  
    ACFE: *Review transactions with large even-dollar amounts*  
    Viabilidad: media-alta  
    Columnas base: `Betrag`, `Sachkonto`, `Soll/Haben-Kennz_`

12. `TST-UNUSED-ACCOUNT-ACTIVITY`  
    ACFE: *Identify credits/debits to previously unused accounts*  
    Viabilidad: media  
    Columnas base: `Sachkonto`, `Soll/Haben-Kennz_`, `Erfassungsuhrzeit`, `Betrag`

## Criterio de priorización aplicado

- **P1**: controles que se implementan en una sola tabla, sin joins a maestros no disponibles.
- **P2**: controles viables con la tabla actual pero con supuestos adicionales (umbrales, baseline temporal o heurísticos).
- Se descartan para esta iteración los tests ACFE que requieren explícitamente:
  - maestro de proveedores/clientes/empleados
  - permisos de usuario por sistema
  - datos de tarjetas, viajes o AR detallado no presentes en `fraud_1`.
