# RF16 — Explicador de 2º nivel (comparación de runs)

## Objetivo

RF16 añade un **agente LLM de segundo nivel al final del grafo** (`second_level_explainer`) que:

- compara resultados entre runs (P2P, O2C o ambos),
- detecta similitudes/concurrencias de señal de fraude,
- propone recomendaciones de auditoría accionables,
- funciona también cuando solo hay un run/familia.

Además mantiene comandos de comparación offline (`list-runs`/`compare-runs`) para operación manual.

## Alcance técnico

Implementación principal:

- `src/erp_fraud/storage/runs_comparison.py`
- `src/erp_fraud/graph/nodes/second_level_explainer.py`
- `scripts/run_rf16_second_level_explainer.py`
- CLI integrada en `src/erp_fraud/cli/main.py`:
  - `list-runs`
  - `compare-runs`

Artefactos de salida RF16 del **nodo del grafo**:

- `run_results/<run_id>/graph/second_level_analysis.json`
- `run_results/<run_id>/graph/second_level_analysis.md`

Artefactos de salida RF16 del **comando compare-runs**:

- `run_results/<analysis_id>/rf16_second_level_analysis.json`
- `run_results/<analysis_id>/rf16_second_level_analysis.md`

## Inputs que consume RF16

Por cada run, RF16 lee (si existen):

- `graph/selected_tests.json`
- `graph/findings.json`
- `graph/hypotheses.json`
- `graph/scores.json`
- `graph/graph_state.json` (`run_metadata`)
- fallback parcial con `report.json`

Prioridad de contexto en modo real:

1. documentación interna del proyecto (KB doc-first),
2. referencias externas indexadas (p. ej., ACFE),
3. fallback determinista solo si falla la llamada LLM o la validación.

Con eso construye un `RunSnapshot` y genera:

- resumen por run (process_family, tests seleccionados, findings, label/confidence),
- similitud entre runs (Jaccard de tests y de fraud_types con hallazgos),
- recomendaciones.

## Comandos

Listar runs disponibles:

```bash
python3 -m src.erp_fraud.cli.main list-runs --base-dir run_results
```

Listar runs en JSON:

```bash
python3 -m src.erp_fraud.cli.main list-runs --base-dir run_results --output-json
```

Comparar runs explícitos:

```bash
python3 -m src.erp_fraud.cli.main compare-runs \
  p2p-real-check-01 o2c-real-fix-01 \
  --base-dir run_results \
  --analysis-id rf16-demo-compare
```

Comparar automáticamente último P2P + último O2C:

```bash
python3 -m src.erp_fraud.cli.main compare-runs \
  --base-dir run_results \
  --auto-latest-p2p-o2c \
  --analysis-id rf16-demo-latest
```

Script operativo equivalente:

```bash
python3 scripts/run_rf16_second_level_explainer.py \
  --base-dir run_results \
  --auto-latest-p2p-o2c \
  --analysis-id rf16-script-demo
```

## Interpretación

- Si hay ambos procesos (P2P + O2C), RF16 evalúa concurrencias cross-process.
- Si hay solo un proceso/run, RF16 genera recomendaciones de mejora local y pide comparación interproceso en siguiente iteración.
- Recomendaciones son deterministas y auditables (no inventan datos fuera de artefactos).

## Criterio de aceptación RF16

- `list-runs` funciona sobre `run_results/`.
- `compare-runs` genera JSON/MD sin errores.
- Modo `--auto-latest-p2p-o2c` selecciona una pareja válida cuando existe.
- Modo single-run sigue generando recomendaciones.
