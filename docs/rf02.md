- CLI:

- Descripciones mínimas en campos críticos
- Tests unitarios RF02
- Verificación de aceptación RF02 (`run_results/rf02-11-verification-20260225/`)

# RF02b - Estado

## Alcance

Validación técnica del dataset antes de ejecutar tests de fraude.

## Entregado

- Definición de severidades (`critical` vs `warning`) para checks técnicos
- Extracción de columnas requeridas desde `TestSpec.data_requirements`
- Checks en DuckDB:
  - columnas requeridas faltantes
  - parseo de fechas/importes
  - % nulos por columna requerida
  - rangos básicos (min/max, negativos)
- Generación de `data_validation_report.json` (estructura estable, ordenada)
- Integración en pipeline: bloquear run solo por errores críticos
- Sección en `report.md` enlazando `data_validation_report.json`
- Tests unitarios RF02b

## Política de severidad

- `critical`:
  - `missing_required_columns`
  - `type_parse_errors_dates`
  - `type_parse_errors_amounts`
- `warning`:
  - `null_percentage_required_columns`
  - `basic_ranges_dates`
  - `basic_ranges_amounts`

## Regla de ejecución

- Si existe algún fallo `critical` -> estado `ERROR` y `should_block_run=True`
- Si solo hay `warning` -> estado `OK` y `should_block_run=False`

## Verificación rápida

```bash
/opt/anaconda3/bin/python -m pytest -q tests/test_rf02b_data_validation.py
```
